# Decision Log テンプレート（refactor-structure）

監査結果と実装記録に使う。該当しない項目は削除せず「該当なし」と書く。

根拠には次のラベルを付ける。

- `【事実】` ファイルや実行結果で確認した内容
- `【推論】` 事実から判断した内容
- `【未確認】` 確認していない、または確認できなかった内容

秘密情報は転記しない。

---

## 1. 監査の条件

| 項目 | 内容 |
| --- | --- |
| 対象パス | |
| 対象外 | |
| 今回の目的 | |
| 基準（コミットSHAなど） | |
| 既存の未コミット変更 | |
| 確認した作業規約 | |
| 検証手段（型検査 / Lint / テスト / ビルド） | |
| 現在の失敗 | |
| 実行権限と予算 | |
| レポート保存先 | 応答内のみ / パス：（既存ファイルを上書きしない） |
| サブエージェント | 不使用 / 担当範囲と回数： |

## 2. 改善案と解決する問題

承認の単位は改善案のID。

```md
- R-01：（改善案を1文で）
  - P-01：（問題の要約）
  - P-03：（問題の要約）
- R-02：（改善案を1文で）
  - P-02：（問題の要約）
- 改善案なし（現状維持）
  - P-04：（維持する理由）
```

## 3. 問題の記録

問題ごとに作成する。

```md
### P-01：（短い題名）

- 優先度：高 / 中 / 低（理由：変更頻度、波及、根拠の確かさ、リスク）
- 対象：`path/to/file.ext:行番号`
- 分類：A 隠れた依存 / B 不要な依存 / C 存在意義の薄い構造
- 観測した事実：【事実】
- 変更や理解の負担：【事実】【推論】
- 同じ理由で変更される根拠：（共通化を提案する場合に必須）
- 現状を維持する選択肢：（維持した場合の影響）
- 最小の改善案：
- 変更予定のファイルと影響範囲：
- 変えてはいけない振る舞い：
- リスクと未確認事項：【未確認】
- 検証方法：（コマンドと確認内容）
- テストへの影響：なし / 機械的な追従のみ（内容） / 検証内容に影響するため分割を提案
```

## 4. 特殊処理の確認

| 対象 | 種類 | 満たしている要件・外部制約 | 過去の障害との関係 | 今も必要か | 設計変更で不要にできるか | 判断 |
| --- | --- | --- | --- | --- | --- | --- |
| `file:行` | retry など | | | | | 維持 / 維持・要確認 / 改善案で解消（R-xx） |

## 5. 未使用判定の確認

| 対象 | 公開API | 動的な呼び出し | 設定・テンプレート参照 | 外部利用者 | テストからの参照 | 判断 |
| --- | --- | --- | --- | --- | --- | --- |
| `file:行` | | | | | | 削除候補 / 未使用の可能性・要確認 / 維持 |

テストからの参照がある場合、削除にはテストの削除が伴うため、このSkillの中では実施しない。

## 6. 扱わない発見事項

| 種類 | 内容 | 根拠 | 提案 |
| --- | --- | --- | --- |
| バグの疑い / 仕様の疑問 / 性能 / テスト品質 / 範囲外の構造 | | | 別の変更として |

## 7. 承認の依頼

```md
実施する候補をIDで指定してください。例：「R-01を提案どおり実施。R-02は見送り」

| ID | 変更内容 | 変更予定ファイル | テストの機械的な追従 | 検証コマンド |
| R-01 | | | なし / あり（内容） | |

「いいね」「続けて」など対象を特定できない返答は、承認として扱いません。
commit、push、依存関係の変更は、この承認に含まれません。
```

## 8. 実装記録

変更単位ごとに作成する。

```md
### R-01

- 承認：（利用者の承認内容をそのまま引用）
- 変更前の検証：（コマンドと結果。既存の失敗を区別）
- 変更内容：（ファイルと要約）
- 変更後の検証：（同じコマンドと結果）
- 計画との差異：なし / あり（再承認の記録）
```

## 9. 完了報告

```md
- 実際の変更：
- 維持した仕様と根拠：
- 実行した検証（変更前 → 変更後）：
- 未実行の検証と理由：
- 差分レビューの結果：（承認範囲のみか、既存変更の保持、副作用の混入）
- 残るリスクと未確認事項：
- 発見したが扱わなかった問題：
```
