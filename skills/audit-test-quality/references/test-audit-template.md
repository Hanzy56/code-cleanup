# テスト監査テンプレート（audit-test-quality）

監査結果と実装記録に使う。該当しない項目は削除せず「該当なし」と書く。

根拠には次のラベルを付ける。

- `【事実】` ファイルや実行結果で確認した内容
- `【推論】` 事実から判断した内容
- `【未確認】` 確認していない、または確認できなかった内容

秘密情報は転記しない。

報告の先頭に要約を置き、提案の要点、本体のバグの疑い、利用者の判断が必要な点を示す。

---

## 1. 監査の条件

| 項目 | 内容 |
| --- | --- |
| 対象パス | |
| 対象外 | |
| 今回の目的 | |
| 基準（コミットSHAなど） | |
| 既存の未コミット変更 | |
| 確認した作業規約 | |
| 検証手段（テスト / カバレッジ / 型検査 / Lint / ミューテーション） | |
| 現在の失敗・skip中のテスト | |
| 実行権限と予算 | |
| レポート保存先 | 応答内のみ / パス：（既存ファイルを上書きしない） |
| サブエージェント | 不使用 / 担当範囲と回数： |

## 2. 候補の一覧

承認の単位は候補のID。

| ID | テスト | 観点 | 分類 | 要約 | 要確認事項 |
| --- | --- | --- | --- | --- | --- |
| T-01 | `file:行` テスト名 | A〜E | 維持 / 書き換え / 統合 / 削除候補 | | |

## 3. 候補の記録

### 維持

```md
### T-01：（テスト名）

- 対象：`path/to/file.test.ext:行番号`
- 検証する仕様や契約：
- 検出できる回帰：
- 懸念した点と維持の理由：
- 要確認事項：（誰に、何を確認すれば判断できるか）
```

### 書き換え

```md
### T-02：（テスト名）

- 対象：`path/to/file.test.ext:行番号`
- 検証する仕様や契約：
- 現在検出できる回帰：
- 問題の根拠：【事実】
- 書き換え案：
- 期待値の出典：（仕様、計算手順、記録など。実装から生成しない）
- 維持する検証：（入力条件、境界条件、実行条件）
- 書き換えで検出できるようになる回帰：
- 本体のバグが現れる可能性と、その場合の扱い：
- 実施した確認：
- 未確認：
```

### 統合・削除

必須項目をすべて記入する。書けない項目が残る候補は、維持に戻すことを検討する。

```md
### T-03：（テスト名）

- 分類：統合 / 削除候補
- 対象ファイル・行番号・テスト名：
- 検証する仕様や契約：
- 現在検出できる具体的な回帰：
- 問題と判断した具体的な根拠：【事実】
- 削除した場合に失われる検出能力：
- 代替として残すテストと、その検証内容：
- 同等だと判断した条件：
  - 入力条件：
  - 境界条件：
  - 実行条件（CI対象、環境、skipの有無）：
- 削除より書き換えが適切ではない理由：
- 実施した確認：
- まだ確認していないこと：【未確認】
- 統合の場合、統合後に残る全ケース：
```

実効的な検証が存在しないと判断する場合は、「絶対に失敗しない」と言える理由を、前段の呼び出しが例外を投げる場合を含めて書く。

## 4. 残存テスト集合の確認

削除・統合候補が担う検証を1行ずつ書き、**残るテスト**を割り当てる。

| 検証（仕様 / 入力・境界 / 実行条件） | 現在のテスト | 処理 | 残るテスト | 残るテストの処理 | 実行されるか | 判断 |
| --- | --- | --- | --- | --- | --- | --- |
| 例：上限ちょうどの値 | T-03 | 削除候補 | `other.test.ts:40` | 維持 | CI対象・skipなし | 代替あり |
| 例：空入力 | T-04 | 削除候補 | なし | | | 固有の検証のため維持へ戻す |

確認事項：

- [ ] 残るテストの列に、削除候補が含まれていない。
- [ ] 代替関係が循環していない（A→B、B→Aなど）。
- [ ] 書き換えに依存する代替は、書き換えを先に行う順序になっている。
- [ ] skip中、CI対象外、環境が異なるテストを、そのまま代替にしていない。
- [ ] 一部だけ承認された場合に、この表を作り直す。

## 5. ミューテーション検証の記録

実施しなかった場合は「未実施」と理由を書く。

| 項目 | 内容 |
| --- | --- |
| 実行許可と予算 | |
| 隔離コピーの場所と作成元（コミットまたは作業ツリー） | |
| コピーから除外したもの（秘密情報など） | |
| 使用ツール | 手作業 / 導入済みの（ツール名） |
| 変異なしでの結果 | |
| 対象リポジトリに差分が増えていないことの確認 | |
| 隔離コピーの扱い | |

| 変異ID | 対象の仕様 | 変異の内容 | 実行したテスト | 変更前の結果 | 変更後の結果 | 解釈 |
| --- | --- | --- | --- | --- | --- | --- |
| M-01 | | | | 検出 / 未検出 / 環境エラー等 | | アサーションが弱い / 無関係な変異 / 振る舞いが変わらない変異 / 不明 |

環境エラー、コンパイルエラー、タイムアウトは「検出」に数えない。

## 6. 承認の依頼

```md
実施する候補をIDと処理で指定してください。例：「T-02を書き換え、T-05とT-06を統合。T-09の削除は見送り」

| ID | 処理 | 変更内容 | 変更予定ファイル | 検証コマンド |
| T-02 | 書き換え | | | |

「いいね」「続けて」など対象を特定できない返答は、承認として扱いません。
プロダクションコード、テスト設定、CI設定、依存関係の変更、commit、pushは、この承認に含まれません。
```

## 7. 実装記録

変更単位ごとに作成する。

```md
### T-02

- 承認：（利用者の承認内容をそのまま引用）
- 残存テスト集合の再確認：
- 変更前の検証：（コマンドと結果。既存の失敗を区別）
- 変更内容：
- 変更後の検証：（同じコマンドと結果）
- 計画との差異：なし / あり（再承認の記録）
- 本体のバグの疑い：なし / あり（根拠と報告内容）
```

## 8. 完了報告

```md
- 残した検証内容：（4の表を実際の結果で更新したもの）
- 削除・統合・書き換えの根拠：
- 実行した検証（変更前 → 変更後）：
- カバレッジ・ミューテーションの比較と、その限界：
- 未実行の検証と理由：
- 差分レビューの結果：（本体の変更なし、既存変更の保持、skip等の混入なし）
- 残る不確実性：
- 発見したが扱わなかった問題：
```
